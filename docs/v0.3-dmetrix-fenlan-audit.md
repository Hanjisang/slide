# DMETRIX / FENLAN 真实样本专项

## 根因

两种格式的原实现把公共 `LayerIndex`/`ImgIndex` 直接交给 `binary.Read`，但真实文件的磁盘布局不同于公共结构体字段顺序。DMETRIX 因此把层级索引尺寸字段错读，累计到第 15 层后触发 `tile index count exceeds safety limit`；FENLAN 同样会把真实索引记录解释为异常数量。安全阈值不是根因。

真实布局为：层级记录 `layer, maxLine, maxRow, indexOffset`；Tile 记录 `layer, line, row, absoluteDataOffset, dataLength`。修复后使用格式私有 disk record，再显式转换为公共运行时结构。

## 安全策略

原有每格式最大索引数量为 2,000,000，保留不变。新增/保留 rows*columns 溢出检查、索引字节数溢出检查，并由 Streamer 对每次 offset/length 做文件边界校验；Tile 数据不再叠加错误的 header 偏移。

## 限制

能力状态仅覆盖上述真实样本；其他厂商版本仍需独立样本验证。DMETRIX/FENLAN 的 vendor SDK、加密文件和非 little-endian 变体不在本专项范围内。
