# v0.3 Go Parser 源码审计

审计日期：2026-08-18

## 输入与结论

- 输入归档：项目根目录 `parser.zip`，仅作为用户提供的开发输入，已由 `.gitignore` 排除。
- 原始代码是 `imageparser/parser` 子模块，不含 `go.mod`、公共 `types`、本地 streamer 与通用图像工具。
- 本项目只迁移目标格式的核心解析算法，并重建可独立编译的最小公共层；未恢复远程 Streamer、原配置中心和原缓存架构。
- 原始归档未提供许可证文件，结论为 `LICENSE_NOT_PROVIDED`。
- 未发现 KFB、TMAP、MDSX、DMETRIX、FENLAN、ZYP、SDPC、CSP、HWP、TRON 的真实切片样本，因此不得把这些格式标为 `AVAILABLE`。

## TMAP 选择

原总路由把 `.tmap` 指向 `tmap01.New`，该实现依赖 `libiViewerSDK2.so`，且其 TMAP07 分支仍错误调用 TMAP06 构造器。v0.3 明确采用 `parser/tmap`：先读取前 6 字节，只有 `TMAP06` 或 `TMAP07` 才进入对应纯 Go 解析器。

## SDK 与许可证边界

原归档包含 CSP Linux/Windows x86-64 二进制，但没有再分发许可；CSP 与 TMAP SDK 头还带有 `All rights reserved`。以下内容不进入公开仓库：

- `libcsp_sdk.so`、`libcsp_sdk.dll`；
- CSP、TMAP、HWP 的厂家 SDK 头与 SWIG 绑定；
- `libDecodeHevc.so`、`libhwp_sdk.so`、`libtronc.so` 等未提供再分发许可的库。

获授权的本地依赖只能放到忽略目录 `vendor-libs-local/`。当前镜像使用 Linux CGO 构建，通过 `dlopen/dlsym` 运行时探测 TRON/HWP；缺任意厂家库仍不影响构建和启动。
运行镜像基于 Debian/glibc，避免 Alpine/musl 无法加载常见厂家 SDK；SDK 的其它共享库依赖仍需由部署方一并提供。

## 安全审计结果

- FileStreamer 基于 `os.File.ReadAt`，拒绝负 offset/size、越界范围和单次超过 64 MiB 的读取。
- Registry 在解析后校验宽高、层数和 block size；每个 Parser 外层有 panic recovery。
- 固定从 `/data/slides/{slideId}` 解析，拒绝非法 ID、符号链接、非普通文件与越出缓存根目录的路径。
- Parser 缓存按路径、大小和 mtime 失效，TTL 30 分钟，最多 128 项；同一切片使用独立互斥锁。
- SDPC 限制层数、尺寸、索引总量和编码图像大小；颜色校正改为每像素有界计算，不保留原实现每组参数约 48 MiB 的无界全局查找表。

## 测试数据审计

仓库、`parser.zip` 附近与当前可访问的测试目录均未发现十种厂家格式样本。原 `_test.go` 使用 `D:\\testdata`、`D:\\BaiduNetdiskDownload`、`/data/imageparser/testdata` 等历史绝对路径，未迁移为有效验收证据。大型样本必须放在仓库外或被忽略的 `data/` 下，不得提交 Git。
