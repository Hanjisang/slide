# v0.3.1 Hotfix

## 监控告警

本版本新增 `MonitoringSnapshotService`，统一提供 components、resources、storageTargets、tasks、queues、parserCapabilities 和 criticalAlerts。`/api/system/health`、`/api/system/metrics`、`AlertService` 和前端全局轮询不再各自采样。

告警规则扩展到基础服务、CPU/内存/磁盘/JVM、Storage Target、任务失败/卡住和队列积压。规则的触发阈值、恢复阈值和防抖次数来自 `alert_rule`；事件记录首次/最后出现、出现次数、异常/健康采样和自动恢复信息。

MySQL 不可用时，健康接口仍返回 `mysql=DOWN`，`InMemoryCriticalAlertBuffer` 暂存故障时间并在数据库恢复后补录事件。前端 AppLayout 每 30 秒轮询活动告警和健康快照，使用 sessionStorage 按事件去重，并显示告警铃铛和活动数量。

## TRON

本机在 `D:\Projects`、仓库、Downloads、Program Files 和 Program Files (x86) 未找到 `libtronc.so`、TRON 样本或相关调用源码。Go Parser 新增 `TRON_SDK_PATH`，Linux CGO 运行时通过 `dlopen/dlsym` 校验公开 API 符号；SDK 目录通过 `TRON_SDK_DIR` 只读挂载，未提交任何第三方库。当前状态为 `SDK_REQUIRED`，不能宣称 `AVAILABLE`。

## HWP

本机未找到 `libhwp_sdk.so`、`hwp_sdk.dll`、HWP 样本或 `GetHwpReader/HwpReadImg` 源码。Go Parser 新增 `HWP_SDK_PATH`，运行时校验 HWP SDK 符号；SDK 目录通过 `HWP_SDK_DIR` 只读挂载，未提交第三方库。当前状态为 `SDK_REQUIRED`，未虚构 Native Parser 或 Bridge。

## 验证边界

本环境已完成 Maven、Python、前端构建、Linux CGO Go 测试和全栈 Compose 构建。真实演练覆盖 MinIO、Slide Worker、Go Parser、MySQL、CPU/内存/磁盘/JVM 阈值、单 Storage Target 以及五类任务失败/卡住；所有测试服务和数据均已恢复，活动告警为 0。没有 TRON/HWP SDK 与真实样本，因此两种格式的 L3-L5 解析仍不能验收。
